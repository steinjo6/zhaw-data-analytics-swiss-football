
Programming environment & recommended subscriptions

In this course, we will mainly work with Python and Visual Studio Code using GitHub Codespaces.

Therefore, you need a GitHub Pro account, which you can apply for via ‘educational benefits’ on GitHub. This web page describes how to do it.

After you have created your own GitHub Pro account, you can create a Codespace from this repository:
https://github.com/mario-gellrich-zhaw/data_analytics.git

We recommend setting up a payment method and limiting the amount to 10 U.S. dollars per month.

Although AI models (LLMs) are part of the GitHub ecosystem, the number of AI credits per month is limited. We therefore additionally recommend purchasing either a Copilot Pro or a Claude Pro subscription. Both can be used from within VS Code via extensions (details will be explained in class).
Evaluation of the project concept presentation

Presentation Outline:

    The presentations of the project concept will be on-site in Winterthur and take place at the beginning of the lectures (large classes) from week 10 onwards (3-4 groups per lecture, 10 min. per group).
    For the presentation, provide a slide set (PDF-Document) and upload it to Moodle (see link below).
    A link to the presentation dates/times is available on Moodle (same link as for the group registration).
    Note that the dates/times of the presentations will determined by the lecturer once the project groups are registered.

To be evaluated:

    Structure & outline (Clear outline presented and followed? Logical flow with recognizable thread? Balanced weighting of parts? Title clear? Names of all students available?)
    Background & problem (Context of the project clear? Problem convincingly motivated?)
    Objective & research question (Clearly defined?)
    Data (Source shown? Structure of the data explained?)
    Methods (Methods appropriate for the research question? Correctly described and justified?)
    Expected results (Plausible? Linked back to the research question?)
    Language (Freely spoken?)
    Quality of the presentation (Quality of graphics, tables & slides according to scientific standards?)

Grading scale (criteria 1–8)
Grade 	Description
6 	Excellent — the criterion is fulfilled completely and convincingly, without notable weaknesses
5 	Good — the criterion is fulfilled well, with only minor weaknesses
4 	Sufficient — the criterion is fulfilled in its essential aspects; basic requirements are met
3 	Insufficient — key elements of the criterion are missing or incorrect
2 	Poor — the criterion is addressed only in fragments
1 	Not fulfilled — the criterion is not addressed / no performance shown

Each of the criteria 1–8 is graded independently on the scale 1–6. The final grade for the presentation of the project concept is the average of these eight grades.
Evaluation of the final project (max. 22 points)
Minimum requirements (9 points)

The project must be a Data Analytics project, i.e., must include content of the Data Analytics module.

The project must integrate several topics presented in the module, at a minimum these are the following:

    Data collection using Web Scraping and/or a Web API. The data must be collected by the group itself; ready-made datasets (e.g. from Kaggle) are not permitted as the primary data source.
    Data preparation and integration: the project must combine data from at least two different sources (e.g. scraped data enriched with data from opendataswiss). The integration step (matching keys, joining, resolving inconsistencies, number of records lost/gained) must be documented.
    Data storage in a SQLite database including SQL queries from within Python.
    Rich non-graphical and graphical exploratory data analysis (EDA).
    Modeling: use of either regression or classification. The research question must go beyond a standard prediction task (e.g. include a comparison between groups, regions, time periods, or data sources).
    Model evaluation using suitable measures of fit (e.g. r-squared, RMSE, accuracy, recall, precision, ...).
    Correct interpretation of model results and measures of fit.
    Documentation of AI usage for creating the code and the presentation (the use of AI is not only allowed but desired), including the advantages and disadvantages you found and where something did not work with the help of AI.
    Making the material (data, Jupyter notebooks, ...) available on Moodle.

Note: The topic will be formally approved by the lecturers at the presentation of the project concept on-site in Winterthur (week 10 onwards). If you are unsure whether your topic meets the requirements and can achieve the points for the overall project (see the details on Moodle), please contact the lecturers before you prepare the project concept. A short email with your topic and research question (2–3 sentences) is enough, and you will get an initial assessment. Overused standard topics (e.g. plain used-car or real-estate price prediction without an extended research question) will be graded lower on creativity.
Additional points, if the following criteria are met (max. 6 points)

    Creativity of implementation (creative is anything not specified in the lessons and exercises).
    Use of a PostgreSQL or similar database (no SQLite!) with, e.g. SQL joins and aggregations from within Python.
    Integration and visualization of geographical data.
    Use of a Chi-squared test, analysis of variance (ANOVA), or correlation analysis (each test must include a p-value).
    Use of k-means clustering in addition to the regression or classification model.
    Code on a publicly available GitHub repository (provide the GitHub project URL in the project presentation).

Project presentation in the form of a video recording (max. 7 points)

To be evaluated:

    Structure & outline
    Topic presentation (Topic clearly defined? How convincingly presented?)
    Content (substance, depth, weighting of parts)
    Language / auxiliary tools (Freely spoken?)
    Quality of the presentation & slides
    Reflection on AI usage: the presentation (slides and video) must include which AI tools were used and how, the advantages and disadvantages you found when using AI, and where something did not work with the help of AI.
    Time keeping: length of presentation in minutes = number of students per group × 5 minutes.

Notes:

→ Use the slide set (PDF) as the basis for the presentation.

→ Show the Python code & live demos only if it improves the understanding of methods and results.

→ Do not just scroll through the code in the Jupyter notebooks without explaining the code and results.

→ AI is a tool, not a substitute for understanding. The evaluation focuses on your ability to explain and justify your data, methods, and results.
